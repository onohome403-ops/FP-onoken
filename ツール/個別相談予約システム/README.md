# 個別相談 予約システム

Googleカレンダーと連携した、**個別相談（オンライン・対面）**の予約ページです。Google Apps Script（GAS）で動くので、サーバー代・月額費用はかかりません。

## できること

- お客様は公開URL（LINEやインスタのプロフィールに貼る）から、空いている枠だけを見て予約できる
- **Googleカレンダーに予定が入っている時間帯は自動で非表示**（予定の詳細はお客様には見えない）
- 予約が入ると、**Zoom会議を自動発行**し、カレンダーに「【個別相談】◯◯様（オンライン）」の予定を作成（場所欄にZoomのURL）
- お客様にZoomの参加URL入りの確認メール、自分に通知メールを自動送信
- Zoomの発行に失敗しても予約は受け付け、自分宛ての通知メールで「URLを手動で送ってください」とお知らせ
- **相談の24時間前に、お客様へリマインドメールを自動送信**（Zoom URL入り）
- 同時に同じ枠を押された場合も、後の人には「埋まりました」と表示（ダブルブッキング防止）

## 受付ルール（初期設定）

| 項目 | 設定 |
|---|---|
| 予約方法 | 個別相談は最初に「オンライン／対面」を選ぶ。オンラインはその場で日時まで予約、対面はお申し込みだけ受けて、こちらから電話して日時・場所を決める。協業面談はオンラインのみ |
| 1枠の長さ | 相談60分＋準備・休憩30分（お客様には60分枠で表示） |
| 月〜木 | 10:30／13:00／14:30／16:00／17:30／19:00／20:30 開始（7枠） |
| 金・土・日 | 9:00／10:30／13:00／14:30／16:00／17:30／19:00／20:30 開始（8枠） |
| 終日休み | 第1・第3月曜日 |
| 予約締切 | 開始の24時間前まで |
| 表示期間 | 今日から30日先まで |
| 終日の予定 | 基本は予約に影響しない（メモ扱い）。タイトルに「休み」「休業」「予約不可」を含む終日予定がある日だけ予約不可 |

ルールはすべて `Code.gs` 冒頭の `CONFIG` で変更できます。

## セットアップ手順（15分ほど＋Zoom設定10分）

1. **https://script.google.com** を開き、「新しいプロジェクト」を作成。名前は「個別相談予約」など
2. 左の歯車（プロジェクトの設定）→「`appsscript.json` マニフェスト ファイルをエディタで表示する」にチェック
3. エディタに戻り、4つのファイルを貼り付け
   - `コード.gs`（最初からある）→ 中身をすべて消して `Code.gs` の内容を貼る
   - `appsscript.json` → `appsscript.json` の内容を貼る
   - 「＋」→「HTML」で **`Index`** という名前のファイルを作り、`Index.html` の内容を貼る
   - 「＋」→「HTML」で **`Cancel`** という名前のファイルを作り、`Cancel.html` の内容を貼る（キャンセル画面）
4. `CONFIG` の `OWNER_NAME`（差出人名）と `SIGNATURE`（メールの署名）を確認して保存
5. 上部の関数選択で **`testListSlots`** を選び「実行」→ 権限の許可画面で自分のアカウントを選んで許可
   （「このアプリは確認されていません」と出たら「詳細」→「◯◯（安全ではないページ）に移動」）
   → 実行ログに空き枠が出ればOK
6. （Zoomを使う場合）下の「Zoom連携の設定」を先に済ませる
7. 関数 **`setupReminder`** を選んで「実行」（追加の権限を求められたら許可）→ リマインドメールの自動送信がONになる
8. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
9. 表示された **ウェブアプリのURL** が予約ページです。LINE・インスタ・名刺のQRコードなどに使ってください

## Zoom連携の設定（10分ほど）

> Zoomの無料プランは1回40分までのため、60分の相談には**有料プラン（Pro以上）**が必要です。

1. **https://marketplace.zoom.us** に自分のZoomアカウントでログイン
2. 右上「Develop」→「Build App」→ **「Server to Server OAuth App」** を選んで作成（名前は「個別相談予約」など）
3. 「App Credentials」に表示される **Account ID / Client ID / Client Secret** を控える
4. 「Information」で会社名・氏名・メールアドレスを入力
5. 「Scopes」→「Add Scopes」で **Meeting** の中の次の2つにチェック
   - `meeting:write:meeting:admin`（会議の作成）
   - `meeting:delete:meeting:admin`（テスト会議・失敗時の削除）
6. 「Activation」→ **「Activate your app」**
7. Apps Script に戻り、左の歯車（プロジェクトの設定）→ 一番下「スクリプト プロパティ」→「スクリプト プロパティを追加」で、次の3つを登録

   | プロパティ | 値 |
   |---|---|
   | `ZOOM_ACCOUNT_ID` | 3で控えた Account ID |
   | `ZOOM_CLIENT_ID` | 3で控えた Client ID |
   | `ZOOM_CLIENT_SECRET` | 3で控えた Client Secret |

8. エディタで関数 **`testZoom`** を選んで「実行」（追加の権限を求められたら許可）
   → ログに「Zoom連携OK」と参加URLが出れば完了（テスト会議は自動で削除されます）
9. 「デプロイを管理」から新しいバージョンでデプロイし直す

**うまくいかない時**
- `Zoom認証エラー(400/401)` → ID・Secretの貼り間違い、またはアプリをActivateしていない
- `Zoom会議の作成に失敗(400/404)` → スクリプト プロパティに `ZOOM_USER_ID` を追加し、値に自分のZoomのメールアドレスを入れる
- Zoomを一時的に止めたい → `CONFIG` の `ZOOM_ENABLED: false`（確認メールは「URLは前日までにご連絡」の文面に戻ります）

> Client Secret はパスワードと同じ扱いです。コードやLINEには貼らず、スクリプト プロパティにだけ保存してください。

> コードを書き換えたあとは「デプロイ」→「デプロイを管理」→ 鉛筆マーク →「バージョン：新しいバージョン」→「デプロイ」で反映されます（URLは変わりません）。

## よくある設定変更

```js
// 仕事用カレンダーや家族カレンダーの予定も空き判定に入れたい
// （名前を変えたら、ここも同じ名前に直す。同じ名前のカレンダーが2つあるとエラーになる）
// カレンダーの名前（左の一覧に出ている名前そのまま）で書ける。IDより名前がおすすめ（公開リポジトリにIDを出さないため）
CHECK_CALENDAR_IDS: ['primary', '家族（仕事ダメ）'],

// 曜日ごとの枠は SLOT_START_TIMES_BY_WEEKDAY で変更（0=日〜6=土）
// 例：木曜日は19:00と20:30をなしにしたい
4: ['10:30', '13:00', '14:30', '16:00', '17:30'],
// 例：水曜日は受付しない
3: [],

// 年末年始を休みにしたい
CLOSED_DATES: ['2026-12-30', '2026-12-31', '2027-01-01'],

// 対面のお申し込みを受け付けるのをやめたい（BOOKING_TYPES の consult の中。方法を選ぶ欄が消える）
IN_PERSON: false,

// 前日の夜まで受け付けたい（12時間前まで）
MIN_HOURS_BEFORE: 12,

// 訪問相談があるので前後30分空けたい
BUFFER_MINUTES: 30,
```

## リマインドメール

- 1時間ごとに自動チェックし、**開始24時間前**になった予約のお客様にメールを送ります（例：明日14:30の相談 → 今日14:30〜15:30の間に送信）
- 本文：日時・Zoomの参加URL／ID／パスコード・当日あるとスムーズなもの・キャンセル用リンク
- 「あるとスムーズなもの」は `CONFIG` の `BRING_ITEMS`、書き出しの一言は `MAIL_INTRO` で変更できます（確認メールと共通）
- 本文の言い回しは `buildConfirmBody_`（確認メール）と `buildReminderBody_`（リマインド）の中で変更できます
- **カレンダーの予定を別の日時に動かせば、動かした後の日時で送られます。予定を削除すれば送られません**
- 開始まで12時間を切ってから入った予約は、確認メールを送ったばかりなので省略します
- 送るタイミングは `CONFIG` の `REMIND_HOURS_BEFORE` で変更できます
- 止めたいときは関数 `stopReminder` を実行
- この仕組みを追加する前に入った予約には、リマインドは送られません

## 予約の種類（個別相談・協業面談）

1つの予約ページで、種類を切り替えられます。URLの最後に付ける言葉で決まります。

| 種類 | 送るURL | 画面とメール |
|---|---|---|
| 個別相談（お客様） | `…/exec`（今までどおり） | ほっくま、相談内容の選択、お客様向けの文面 |
| 協業面談（協業先） | `…/exec?type=partner` | 会社名の入力欄（必須）、「面談の目的・ご用件」欄、ビジネス向けの文面（持ち物や「無理なおすすめはしません」は入らない） |

- 枠の時間・長さ・締め切り・Zoom・キャンセルリンクは共通です。同じ時間に両方の予約が入ることはありません
- カレンダーの予定名は `【個別相談】` と `【協業面談】` で分かれます。通知メールの件名にも種類が入ります
- 種類ごとの見出し・説明文・入力欄・文面は、`CONFIG` の `BOOKING_TYPES` で変えられます
- 種類を増やすときは、`BOOKING_TYPES` に1つ足し（例：`seminar: { … }`）、`…/exec?type=seminar` を送ります
- 知らない言葉が付いていたときは、個別相談として表示します

## 対面のお申し込み

個別相談の予約ページは、最初に「**1 ご相談の方法を選ぶ**」で「オンライン／対面」を選びます（最初はオンラインが選ばれた状態）。

| 選んだ方法 | 画面の流れ | その後 |
|---|---|---|
| オンライン | 日付 → 時間 → お客様情報 → 予約確定 | これまでどおり。Zoom・カレンダー・確認メール・リマインド・キャンセルリンク |
| 対面 | すぐにお客様情報（日時は選ばない）→ お申し込み | 小野から電話して、日にちと場所を決める |

**お客様が対面を選んだとき**
- 「日にちと場所は、小野からお電話でご相談して決めます」の説明と、「お電話のつながりやすい時間帯」の欄が出る
- ボタンは「この内容で申し込む」。完了画面は「お申し込みを受け付けました」と、お電話先の番号
- 「【お申し込み受付】対面での個別相談」のメールが届く（小野から電話すること・当日の流れ・あるとスムーズなもの）
- カレンダーには何も入らない。Zoom・リマインド・キャンセルリンクもない（取り消しはメールへの返信）

**自分がやること**
1. 「【対面希望・要電話・個別相談】お名前 電話番号」のメールが届く（つながりやすい時間帯も書いてある）
2. お客様に電話して、日にちと場所を決める
3. 決まったら、自分でカレンダーに予定を入れる（その時間はWeb予約に出なくなる）。移動時間が要るなら、前後にも予定を入れる

**お客様に見せる自分の電話番号**（任意）
- スクリプト プロパティに `OWNER_PHONE`（例：自分の携帯番号）を登録すると、確認メールに「お電話は ◯◯ からおかけします」と入る。知らない番号に出ない方にも安心してもらえる
- このコードは公開リポジトリにあるので、番号はコードに書かず、スクリプト プロパティにだけ入れる

協業面談（`?type=partner`）では、方法を選ぶ欄は出ません（オンラインのみ）。

## お客様によるキャンセル

- 確認メールとリマインドメールに、キャンセル用のリンクが入ります
- リンクを開くと確認画面が出て、「キャンセルする」を押したときだけ取り消されます（開いただけでは取り消されません）
- 取り消すと、カレンダーの予定とZoom会議が自動で消え、お客様には「キャンセル受付」、自分には「【キャンセル】」のメールが届きます
- 日程の変更は、これまでどおりお客様がメールに返信 → 自分でカレンダーの予定を動かします
- 受付期限は `CANCEL_MIN_HOURS_BEFORE`（今は 0 = 開始時刻まで）。例：前日までにしたいなら `24`
- リンクを付けたくなくなったら `CANCEL_ENABLED: false`（メールは「返信でご連絡ください」の文面に戻ります）
- リンクを開いても予約ページが出ない・エラーになるときは、`WEB_APP_URL` にデプロイしたURL（…/exec）を貼ってデプロイし直す
- この仕組みを追加する前に入った予約には、リンクは付きません

## 運用のコツ

- **対面の相談は、自分でカレンダーに予定を入れる**だけでOK。その時間はWeb予約に出なくなります（お客様がWebで対面を申し込んだときの流れは「対面のお申し込み」）
- 対面の前後に移動時間があるなら、移動時間も予定として入れておくと安心です
- **予約を止めたい日・時間もカレンダーに予定を入れるだけ**でOK（「ブロック」などの仮予定でも可）
- 終日予定の「休み」を入れれば、その日は丸ごと予約不可になります
- 招待を「不参加」にした予定は、空きとして扱います
- Zoomは「待機室あり」で作成されます。お客様が入室したら、自分が許可して開始してください
- Zoomの会議は自分のZoomアカウントの「ミーティング」一覧にも入ります
- 自分の手で予約をキャンセルするときは、カレンダーの予定に加えてZoomの会議も削除してください（お客様がリンクから取り消した場合は両方自動で消えます）
- 予約の変更は、お客様が確認メールに返信 → カレンダーの予定を手動で移動してください
