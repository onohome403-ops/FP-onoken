# 引継ぎ：商談記録まとめ機能

面談メモや録音の要約から、社内書式の商談記録を下書きする仕組みの引継ぎ資料です。
別のAIや担当者に引き継ぐときは、このファイルをそのまま渡してください。

---

## 1. 仕組みの全体像

| 項目 | 内容 |
|---|---|
| ツール | 商談記録まとめ（ブラウザで使うページ） |
| URL | https://claude.ai/artifact/FSjHkrpZEQhG1anJiHmJQF （本人のみ閲覧可。共有はページの「共有」から） |
| 元ファイル | `商談記録まとめ/商談記録まとめ.html` |
| 動き | 面談メモを貼る →「商談記録にまとめる」→ Claudeが書式に沿って下書き ＋ 記載漏れチェック → 確認・修正してコピー |
| 保存 | 入力内容はページに保存されない（個人情報を残さないため） |
| 利用枠 | 自動作成は、閲覧している人のClaudeの利用枠を使う。初回に利用許可の確認が出る |

**使い方の流れ**
1. 録音の要約（AI議事録）や手書きメモを、そのまま貼り付ける
2. 下書きと「記載前に確認してください」の欄を見て、要確認の箇所を埋める
3. 社内システムに貼り付ける

ツールが使えないときは、下の「6. 別のAIで使う場合の指示文」をチャットに貼れば同じことができる。

## 2. 記録の書式（社内研修の記入例に準拠）

```
【面談者】
・面談者全員の続柄・属性（複数の場合は全員）
・面談の場所・形態（ご自宅にて面談／Zoomにて面談 など）

【お客さまのご要望（ヒアリングした内容）】
・意向、不安、状況。続けたい保険や見直し不要の保険があれば、その理由も

【見直しに至った経緯・理由】
・見直しを考えたきっかけ（保障内容がわからない、担当者の退職、ライフイベント、保険料の上昇 など）

【ご要望に対してご案内した内容】
・まず公的保障の説明 → お客さまの反応 → それでも見直したい意向かの確認
・その後に、その他の説明内容

【提案した保険種類・保険会社・保険商品】
・推奨保険会社を何社案内したか、推奨理由（ニーズとの合致）
・推奨保険会社以外・推奨なしの場合は「理由：〜」

【乗換契約についての説明】（既存契約の解約・減額・失効を伴う場合のみ）
・デメリットを中心に説明
　免責期間（待機期間）による無保険状態のリスク
　既往症や健康状態による引受謝絶・条件付き加入
　保険料が高くなる可能性（加入年齢の上昇）
　特約や保障の細かな条件の変化
・説明済⇒ご了承済
・次回面談時に、もう一度確認するとお約束

【提案した結果】
・申込み・検討継続・見送り
・契約をお預かりした場合は、お客さまがその商品を選んだ具体的な理由

【次回面談で行うこと】
・プラン提示、乗換の再確認、書類の準備 など

★次回：日時・場所
```

## 3. コンプライアンス部門が必ず確認する4つのPOINT

| POINT | 確認されること | 記録に書くこと |
|---|---|---|
| ① 経緯 | なぜ見直したいご意向があったのか | 【見直しに至った経緯・理由】 |
| ② 公的保障 | 公的保険をどう説明したか（過剰な提案をしていないか） | 説明内容、お客さまの反応、それでも加入したい意向の確認 |
| ③ 比較推奨 | 推奨商品・推奨理由（比較推奨販売をしているか） | 案内した社数、選んだ理由 |
| ④ 乗換 | メリット・デメリットをどう説明したか（保険業法第300条の不適正な乗換募集の防止） | デメリット中心の説明、説明済⇒ご了承済、次回の再確認 |

## 4. 下書きを作るときのルール

**書かないもの**
- 実名以外の個人情報（住所の番地、電話番号、生年月日、証券番号、勤務先名）
- 第三者（他のお客さま、紹介者、友人）の名前や健康情報
- 他社・他の担当者を悪く言う表現（「付き合いで入る人が多い」など）
- 出典を確かめられない統計、政治・経済についての個人的な意見
- 雑談、ニュースの話題、お客さまを急がせる表現（「今月中まで」など）
- 性別の役割などに関する、不適切と受け取られかねない発言
- AI議事録の末尾にある「AIからの提案」（面談で実際に話した内容ではないため）

**書き方**
- メモにない事実は作らない。わからないところは「要確認」と残す
- 1行1事実の箇条書き。補足は全角スペースで字下げ
- 試算の金額は「〜を仮定した試算で、保証された金額ではない」と書く
- 健康状態の詳細は「告知書のとおり」とし、記録には細かく書かない
- 例え話（「仮に高度障害になったら」）は、仮定の話であることがわかるように書く

**AI議事録で起きやすい誤り**
- 金額の単位・桁（「ドル」になっている、30万円が30,000円になっている など）
- 社名の聞き違い（花咲く保険 → はなさく生命、など）
- 話者の取り違え（担当者の事例が、お客さまの話になっている）
- 地名が人名になる（上山市 → 上山さん）
- 複数の面談や別のお客さまの話が混ざる

## 5. よく出る「記載前の確認点」

| 場面 | 確認すること |
|---|---|
| 乗換全般 | デメリットの説明と「説明済⇒ご了承済」。新しい契約の成立後に旧契約を解約し、保障の空白を作らない |
| 加入から短期間での乗換 | 元本割れでも、お客さまに利益があることを同じ条件で比べて示す。誰が言い出したかを記録 |
| 失効した契約からの加入 | 復活できるかどうかの説明 |
| 変額保険・外貨建保険 | 元本保証がないこと、費用、為替リスク、市場価格調整、契約締結前交付書面の交付、適合性（投資経験・リスク許容度）の確認 |
| 投資信託・NISA | 証券の仲介にあたるため、会社の証券用の記録にも残す。毎月分配型は、元本の払い戻しを含む場合があることを説明 |
| お子さまの医療保険 | 自治体の子ども医療費助成を説明したうえでの加入の意向 |
| 自営業・経営者 | 国民健康保険か社会保険か（傷病手当金や遺族年金が変わる） |
| 高額な必要保障額の試算 | 障害年金・遺族年金などを差し引いた不足額か。生活費の前提を誰が決めたか |
| 告知 | 健康状態の発言と告知内容が合っているか。お客さまご自身が回答したことを記録（告知妨害の防止） |
| 受取人・指定代理請求人 | 死亡保険金の受取人がご本人になっていないか。代理請求人はご本人以外か |
| 同業者・親族との契約 | 交換契約・特別利益の提供（手数料の還元など）にあたらないか。親族の場合は社内の届け出 |
| 火災保険の請求 | 経年劣化は対象外。「保険が使えるかは保険会社が判断する」と伝えたか |
| 面談場所 | カフェなどでは、周りに会話が聞こえない配慮 |

## 6. 別のAIで使う場合の指示文

以下をコピーして、面談メモの前に貼り付ける。

```
あなたは生命保険・損害保険の募集人を支える記録作成アシスタントです。
以下の面談メモから、保険募集の商談記録を作成してください。

【書式】
【面談者】【お客さまのご要望（ヒアリングした内容）】【見直しに至った経緯・理由】
【ご要望に対してご案内した内容】【提案した保険種類・保険会社・保険商品】
【乗換契約についての説明】（既存契約の解約・減額・失効を伴う場合のみ）
【提案した結果】【次回面談で行うこと】★次回：日時・場所

【必ず読み取れるようにする4点】
1. 見直しに至った経緯
2. 公的保障の説明と、それでも加入したい意向の確認（過剰な提案でないこと）
3. 推奨保険会社の案内数と推奨理由（比較推奨）
4. 乗換のデメリット説明と「説明済⇒ご了承済」（保険業法第300条）

【ルール】
- メモにない事実は書かず「要確認」と残す
- 丁寧で簡潔な業務文体（〜をご説明、〜とのこと、〜と仰せ）。1行1事実の箇条書き
- 住所の番地・電話番号・生年月日・証券番号・勤務先名、第三者の名前や健康情報は書かない
- 他社批判、出典不明の統計、雑談、AI議事録の「AIからの提案」は書かない
- 試算額は保証されないことがわかるように書く
- 記録の後に「記録として残す前の確認点」を箇条書きで付ける
  （4点の欠落、乗換の了承、告知、受取人、変額・外貨建の説明、金額の誤りなど）

【面談メモ】
（ここに貼り付け）
```

## 7. ツールの直し方

- 書式の項目：`商談記録まとめ.html` の `SECTIONS`
- AIへの指示（ルールや確認点）：同じファイルの `buildPrompt` 関数
- 追加できる項目（意向の変化、ご家族・ご同意の状況、その他特記事項）：`#extras` のチェックボックス
- 直したら、同じURLで公開し直す（Claude Codeで「商談記録まとめを更新して」と依頼すればよい）
